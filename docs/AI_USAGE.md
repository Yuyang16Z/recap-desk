# AI 使用与验证记录

## 1. 使用了哪些 AI 工具

| 工具 | 用在哪里 | 角色 |
|---|---|---|
| Claude Code（Claude Opus 5.5） | 读接口文档、探测真实接口、方案设计、编码、调试、写文档；派生子 Agent 分别写单元测试与测试说明、调研投顾规模与监管依据 | 开发协作者（AI Coding） |
| DeepSeek（`deepseek-chat`，接口实际返回的模型名为 `deepseek-flash`） | 产品运行时：Agent 取证、撰写复盘稿、AI 合规复核 | 产品内的大模型 |

候选人负责：选择场景与目标用户、定义成功标准与非目标、确定数据口径、设计 AI/系统/人的职责边界、审阅每一版生成结果、决定修复方案。下面记录 AI 参与的环节，以及其中被发现并修正的错误。

## 2. AI 参与的环节

1. **接口理解**：让 AI 读取扶摇的 `llms-full.txt`（约 50 万字符），整理出可用于复盘的接口与参数；随后**用真实 Key 逐个调用 16 个接口**核对返回结构，不只凭文档写代码。
2. **编码**：后端取数、Agent 循环、校验器、前端工作台的初稿由 AI 生成，每一版都用真实数据跑通后再保留。
3. **测试**：由子 Agent 根据代码编写离线单元测试（mock `fetch`），并用冒烟脚本跑故障演练、记录实际结果（见 [TESTING.md](TESTING.md)）。
4. **文档**：README 与本记录由 AI 起草，数字均取自实际运行结果。

## 3. 修正过的错误与不合理结果

### A. 数据与口径（真实调用后发现，与文档或直觉不符）
| # | 发现 | 修正 |
|---|---|---|
| 1 | 文档写缺少 Key 时返回 `code=2001`，实测返回 `code=2003 "Missing X-api-key"` | 两种都按鉴权失败处理，不重试 |
| 2 | 行情快照的 `timestamp` 是查询时刻（周末查询得到的是周日时间），不是收盘时刻；快照只提供"最新"行情 | 指数改用日K按日期取收盘价；涨跌家数只在"所选日 = 最近收盘日且不在下一交易日盘中"时出具，否则标为缺失 |
| 3 | AI 初版方案拿"上证指数 + 深证成指"的成交额相加作为两市成交额，但深证成指只含 500 只成分股 | 改为上证综指 + 深证综指（399106.SZ）口径，并在事实底稿中写明 |
| 4 | `anomaly-analysis-list`（个股异动原因列表）周末返回空数组；日期范围异动解读的记录里没有股票代码字段 | 改用 `/api/news/anomaly/analysis` 按日期取数，从 `link_url` 的 `thsHqCode` 解析代码再匹配个股 |
| 5 | `anomaly-analysis-stock` 对当日涨停股返回空 | 不依赖该接口，统一从日期范围异动解读建立"代码 → 解读"索引 |
| 6 | `deepseek-chat` 实际被路由到 `deepseek-flash` | 调用日志记录接口返回的真实模型名，在页面「工具调用」中展示 |
| 7 | iFinD 新闻检索会混入百科页面，也会返回较早的旧文 | 时间窗限定为所选日前 3 天至当日，晚于所选日的结果丢弃，百科类来源标注"慎用" |

### B. 大模型输出错误（冒烟运行中发现）
| # | 现象（真实输出） | 修正 |
|---|---|---|
| 8 | **张冠李戴**：模型把新华传媒的"近 5 根日K累计上涨 61.1%"（F47）同时写到阳光乳业和电魂网络名下 | 新增**实体一致性校验**（`entity_mismatch`，阻断级）；提示词同步要求"没有的个股数据不要写，不要借用编号" |
| 8b | 第一版校验按逗号切分句判断，线上运行时误拦了"新华传媒{{F48}}，收盘封单额{{F35}}"：中文主语会跨逗号延续 | 改为按整句判断：句内离占位符最近的前一个股票名是它自己，或它所在的分句已点名该股，就放行；整句没提到该股票，或数字落在别的股票名下，才判为张冠李戴 |
| 8c | 回归样例稿时又误拦了"东方嘉盛、吉大正元、尖峰集团连板高度均为{{F24}}"：并列句共用一个值 | 补充"所在分句已点名该股即放行"的规则。原错误、主语延续、并列句三种情况都写进了单元测试（`test/entity.test.js`） |
| 9 | 模型把"沪深300 / 科创50 / 北证50"里的数字判为未溯源数字（误报） | 增加带数字的指数名白名单，并从事实标签自动提取实体名 |
| 10 | 模型在正文里写内部编号，如"（E7、E9）""E11–E14" | 规范化时把这些编号移出正文、并入 refs（含区间展开）；提示词要求编号只写进 refs |
| 11 | 渲染出"第第1名""近近5根日K"：渲染值已含"第…名"等字词，模型又在占位符外写了一遍 | 渲染时去掉占位符前后的重叠字（前后端同一算法），并在提示词中给出写法示例 |
| 12 | 模型照抄事实标签"连板股家数（2板及以上）"，其中的"2"触发未溯源拦截 | 事实标签改用中文数字（"二板及以上""近五根日K"），减少模型照抄带来的误报 |
| 13 | 事实句夹带判断，如"封板率 54.6%，显示涨停个股的封板稳定性一般" | 新增 `fact_has_inference` 提醒，要求拆成单独的推断句 |
| 14 | 模型把 iFinD 新闻里的政策表述说成"相关异动解读提及" | 未完全解决：依据编号指向的真实来源可以在右侧面板核对，已列入 README 已知边界，需人工复核措辞 |

### C. 优化阶段新发现的问题（第二轮）
| # | 现象（真实输出） | 修正 |
|---|---|---|
| 17 | **Agent 发现了我的 bug**：它在主线判断里指出"摘要写机器人题材 5 只，工具却返回 12 只，存在冲突"。排查后确认，题材成员工具复用了同名事实，但两者口径不同：基础数据按"+"拆分后精确匹配标签，工具按包含关键词匹配，会把"人形机器人"等也算进去 | 工具改为输出独立事实"涨停原因包含"X"字样的个股数"，并在口径里写明两者的区别 |
| 18 | 渲染出"后者前一交易日为前一交易日2只" | 前一交易日的题材计数只渲染数字（标签里已写明"前一交易日"）；去重规则扩展为"占位符前 8 个字内已出现渲染值开头的字词就去掉" |
| 19 | 模型写出"创业板指收于下跌0.39%"："收于"后面接了涨跌幅 | 新增搭配校验 `unit_mismatch`（阻断级，可被自修复处理） |
| 20 | 主线判断里出现证据外的数字，如自行加总的"合并后16只" | 判断中的数字必须能在所引事实或证据里找到，否则在面板上标出问题；但只有引用了不存在的编号、或没有有效支持证据时，才把结论降为"存疑" |
| 21 | 多日评测显示，模型最常见的问题是未溯源数字和搭配错误（见 [EVAL.md](EVAL.md)） | 加入"校验器在环"的自修复：未通过校验的 AI 句子带着错误原因交还模型重写一轮，修后必须重新通过校验才替换原句，修不好的保留原句交人工 |

## 4. 怎么验证 AI 的产出

- **先探测，后编码**：每个接口先用真实 Key 调一次，确认字段、单位、时间戳语义，再写取数代码。
- **交叉核验写进产品**：涨停池记录数与统计接口的涨停家数比对，炸板池与炸板家数比对，天梯最高板与统计最高板比对，封板率与家数自洽。2026-10-16 实测：59 = 59，49 = 49。
- **逐句审阅生成稿**：每次冒烟运行都打印全部句子和校验结果，逐句与事实底稿对照。错误 8–14 都是这样发现的。
- **故障演练**：接口失败、数据过期、大模型不可用、注入违规句，确认产品不会静默产出"正常"结论（见 TESTING.md）。
- **线上复测**：部署到 Render 后在线上实例完整生成一次（18.5 秒，接口 32 次，Agent 11 次，0 失败）。
