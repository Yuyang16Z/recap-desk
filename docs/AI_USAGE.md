## 1. 使用了哪些 AI 工具

| 工具 | 用在哪里 | 角色 |
|---|---|---|
| Claude Code（Claude Opus 5.5） | 读接口文档、探测真实接口、方案设计、编码、调试、写文档；派生子 Agent 分别写单元测试与测试说明、调研投顾规模与监管依据、独立审查代码 | 开发协作者（AI Coding） |

## 2. AI 参与的环节

1. **接口理解**：让 AI 读取扶摇的 `llms-full.txt`（约 50 万字符），整理出可用于复盘的接口与参数；随后**用真实 Key 逐个调用 16 个接口**核对返回结构，不只凭文档写代码。
2. **编码**：后端取数、Agent 循环、校验器、前端工作台的初稿由 AI 生成，每一版都用真实数据跑通后再保留。
3. **测试**：由子 Agent 根据代码编写离线单元测试（mock `fetch`），并用冒烟脚本跑故障演练、记录实际结果（见 [TESTING.md](TESTING.md)）。
4. **文档**：README 与本记录由 AI 起草，数字均取自实际运行结果。
5. **调研**：子 Agent 检索投顾人数与监管条文，只交在原文页面上核对过的内容，未核实的标"未核实"后跳过。写进 README 前，我又打开原文页面，逐一抽查了三条关键出处：财联社的 89265 人、国务院公报中《证券投资顾问业务暂行规定》第十六／十九／二十七／二十八条、网信办《生成式人工智能服务管理暂行办法》第二条。调研同时发现，第三方数据（Choice）与中证协官网口径不一致，因此 README 只引用中证协口径的一个数字，不跨来源拼接增长率。

## 3. 修正过的错误与不合理结果

### A. 数据与口径（真实调用后发现，与文档或直觉不符）
| # | 发现 | 修正 |
|---|---|---|
| 1 | 文档写缺少 Key 时返回 `code=2001`，实测返回 `code=2003 "Missing X-api-key"` | 两种都按鉴权失败处理，不重试 |
| 2 | 行情快照的 `timestamp` 是查询时刻（周末查询得到的是周日时间），不是收盘时刻；快照只提供"最新"行情 | 指数改用日K按日期取收盘价；涨跌家数只在"所选日 = 最近收盘日且不在下一交易日盘中"时出具，否则标为缺失 |
| 3 | AI 初版方案拿"上证指数 + 深证成指"的成交额相加作为两市成交额，但深证成指只含 500 只成分股 | 改为上证综指 + 深证综指（399106.SZ）口径，并在事实底稿中写明 |
| 4 | `anomaly-analysis-list`（个股异动原因列表）周末返回空数组；日期范围异动解读的记录里没有股票代码字段 | 改用 `/api/news/anomaly/analysis` 按日期取数，从 `link_url` 的 `thsHqCode` 解析代码再匹配个股 |
| 5 | `anomaly-analysis-stock` 对当日涨停股返回空 | 不依赖该接口，统一从日期范围异动解读建立"代码 → 解读"索引 |
| 6 | `deepseek-chat` 实际被路由到 `deepseek-flash` | 调用日志记录接口返回的真实模型名，在页面「工具调用」中展示 |
| 7 | iFinD 新闻检索会混入百科页面，也会返回较早的旧文 | 时间窗限定为所选日前 3 天至当日，晚于所选日的结果丢弃，百科类来源标注"慎用" |

### F. 第四轮：独立代码审查（2026-10-18）
做法：派生一个子 Agent 只读审查前后端，要求每条发现都在隔离环境里复现（外部接口全部 mock，另起离线服务副本，不碰项目数据），并写明位置、复现结果和修复建议。审查给出 20 条（高 4、中 11、低 5），我逐条核对后修复，每条补回归测试（`test/hardening.test.js` 与 `test/server.test.js` 新增 22 条）。修复后用审查原文里的例句复测：漏报的 13 句全部被拦下，4 句中性表述不再误报。

| # | 发现（审查实测） | 修正 |
|---|---|---|
| 32 | **高**："缺失不写成正常"没有被程序强制。涨停池缺失时，模型稿里一句待确认都没写，门禁照样放行；待确认句确认后改写成"数据完整，情绪正常"仍算已确认；删掉待确认句也能提交 | 每个缺失项和核验提示由系统追加一条锁定的待确认句（带「系统」标记，不能删除或改写，只能核实后确认保留）；改写文字会让之前的确认失效 |

| 56 | 规则改完后重跑多日评测，平均待确认句从 4 句升到 5.38 句。逐句查看 2026-09-30 的真实输出发现，模型仍会为缺失项自己写待确认句（"全市场涨跌家数缺失……""涨停池记录数与统计接口口径不一致……"），与系统追加的两句锁定说明重复，投顾要多确认两次，定稿也啰嗦 | 撰写提示词明确不再为缺失和核验问题单独写待确认句；生成时再做一次确定性去重：AI 写的、没有引用数字事实的待确认句，如果覆盖了某个缺失或核验标题 80% 以上的相邻字对，就软删除并标注"与系统说明重复"，投顾可以恢复。改完再跑一轮：平均待确认 4.5 句，8 篇里共有 4 句重复被自动删除 |
| 57 | 「故障演练」展开后，复选框被 `.left input { width: 100% }` 撑满整行，文字掉到下一行。之前的截图从没展开过这个面板，所以一直没发现 | 复选框单独恢复为自身宽度，与文字同行 |
| 58 | 生成按钮下的提示写着"约 40–90 秒"，多日评测实测平均 24.7 秒、最长 34.2 秒 | 改为"约 20–40 秒" |
| 59 | 自修复记录里，模型的说明写着"删除未溯源日期「10月15日」"，修订稿里却仍保留这个日期，被校验器判为未修好（系统没有轻信模型的自述） | 撰写和自修复提示词都写明：交易日写 {{DATE}}，新闻事件日期改用"前一交易日晚间"这类相对说法 |

## 4. 怎么验证 AI 的产出

- **先探测，后编码**：每个接口先用真实 Key 调一次，确认字段、单位、时间戳语义，再写取数代码。
- **交叉核验写进产品**：涨停池记录数与统计接口的涨停家数比对，炸板池与炸板家数比对，天梯最高板与统计最高板比对，封板率与家数自洽。2026-10-16 实测：59 = 59，49 = 49。
- **逐句审阅生成稿**：每次冒烟运行都打印全部句子和校验结果，逐句与事实底稿对照。错误 8–14 都是这样发现的。
- **故障演练**：接口失败、数据过期、大模型不可用、注入违规句，确认产品不会静默产出"正常"结论（见 TESTING.md）。
- **线上复测**：部署到 Render 后在线上实例完整生成一次（18.5 秒，接口 32 次，Agent 11 次，0 失败）。
