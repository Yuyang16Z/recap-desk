# 测试说明

本文记录复盘稿工作台的测试方法、用例和**实际观察到的结果**。实际结果来自三处：离线单元测试（`npm test`）；2026-10-17 本地和 Render 线上的真实接口冒烟；在页面上手动走完的端到端流程。没有执行的用例写明“未执行（原因）”，不做推断。

## 1. 怎么跑

### 1.1 单元测试（离线，不访问任何真实接口）

```bash
cd recap-desk
npm test          # 即 node --test "test/*.test.js"，Node ≥ 21（glob 参数），无新增依赖
```

- 测试框架是 Node 内置的 `node:test` + `node:assert/strict`。全局 `fetch` 由 `t.mock.method` 替换，测试里的密钥都是假值（`unit-test-dummy-key`）。
- `test/server.test.js` 把 `server.js` 和 `lib/` 复制到系统临时目录后启动。这样不读 `.env.local`，不写项目里的 `data/runtime`，上游地址统一指向 `127.0.0.1:9`。测试结束后临时目录会被删除。

### 1.2 冒烟脚本（真实扶摇 + DeepSeek，读取 `.env.local`）

```bash
node scripts/smoke.mjs --audience=steady --simulate=fuyao:limit_up_pool,stale_stats      # (a) 不传日期，涨停池失败 + 统计过期
node scripts/smoke.mjs --date=2026-10-16 --audience=steady --simulate=llm_down,inject_violation   # (b) 大模型不可用 + 注入违规句
node scripts/smoke.mjs --date=2026-10-17 --audience=steady                               # (c) 周六
```

脚本不启动 HTTP 服务，也不落盘。它会打印阶段和告警行、`metrics`、`gate`、`gaps`、`dq`，以及逐句渲染结果和 FLAGS。每次真实调用耗时约 1–25 秒，并产生少量调用费用。

### 1.3 产品内故障演练

在页面左侧展开「故障演练（验证异常处理）」，勾选后点生成即可：

| 勾选项 | `simulate` 值 | 作用 |
|---|---|---|
| 涨停池接口失败 | `fuyao:limit_up_pool` | 该 label 的扶摇调用直接抛 5003，不发请求 |
| 指数日K接口失败 | `fuyao:index_kline` | 7 条指数日K全部失败 |
| 涨停统计返回过期日期 | `stale_stats` | 把统计接口返回的 `trade_date` 改成前一交易日 |
| 大模型不可用（降级） | `llm_down` | Agent 与撰写阶段都抛 `LlmError`，走模板稿 |
| 注入违规句（测合规拦截） | `inject_violation` | 在末节追加一句含预测、荐股、收益承诺的违规句 |

接口另外接受 `fuyao:limit_up_statistics` 和 `fuyao:anomaly_analysis`（见 `server.js` 的 `SIMULATIONS`），页面上没有对应勾选项。

### 4.3 极端与合规边界
