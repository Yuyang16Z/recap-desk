# 复盘稿工作台 · AI 投顾盘后复盘助手

> 收盘后，投资顾问点一次「生成」，约 20–30 秒拿到一份复盘稿草稿。稿中每个数字都能点开查到接口字段、时点和口径，每句话都标明是事实、推断还是待确认。Agent 会先给出「主线判断」，列明支持证据、反证和待补证据；稿件会写出与前一交易日相比的变化。预测、荐股、收益承诺、来路不明的数字和张冠李戴会被校验器拦下，AI 写的问题句会先带着错误原因自动重写一轮。合规审核通过后才生成可发布的定稿；合规沉淀的禁用表述会立即作用于之后的校验和生成。

- **在线体验**：https://recap-desk.onrender.com（Render 免费实例，新加坡区；北京时间 9:00–23:00 由 GitHub Actions 每 10 分钟访问一次以保持唤醒，其他时段首次打开约需 30–60 秒冷启动。2026-10-18 用站长工具从国内 53 个节点 ping：域名正常解析，多数节点 150–270ms 可达，浙江杭州多线 163ms）
- **源代码**：https://github.com/Yuyang16Z/recap-desk
- **测试说明**：[docs/TESTING.md](docs/TESTING.md) · **多日评测**：[docs/EVAL.md](docs/EVAL.md) · **AI 使用与验证记录**：[docs/AI_USAGE.md](docs/AI_USAGE.md) · **演示视频**：121 秒，用自动化浏览器操作线上实例录制，随笔试提交包提供
- **数据**：同花顺金融数据（扶摇 API，12 类接口）+ iFinD MCP（新闻检索）；**模型**：DeepSeek（OpenAI 兼容接口，可换）

## 1. 问题定义

### 目标用户
| 角色 | 在流程里做什么 | 本产品给他什么 |
|---|---|---|
| **持牌投资顾问（主用户）** | 每个交易日收盘后给客户群/APP 写盘后复盘 | 一份数据齐全、可溯源的草稿和证据面板，只需修改和确认 |
| **合规审核岗（次用户）** | 审核对客内容，退回违规表述 | 提交前已拦掉的违规项，以及事实/推断/待确认的清晰标注，减少逐字排查 |
| 投顾服务的客户（间接） | 阅读复盘 | 不直接使用本产品；收到的是经人工审核的内容 |

### 真实工作流（现状）
15:00 收盘 → 在行情软件里看指数和成交额 → 打开涨停复盘页看涨停、炸板、连板梯队 → 翻题材和板块排行 → 逐个查强势股、跌停股的异动原因和新闻 → 写稿 → 自查数字 → 提交合规 → 按意见修改 → 当晚发布。

### 痛点（可衡量）
1. **耗时**：数据散落在多个页面，收集加撰写占用大量收盘后时间（单篇耗时是待实测的基线，见第 7 节）。
2. **数字差错**：手工抄录容易出现单位（亿/万）错误；口径也容易用错，例如拿深证成指成交额代表深市成交，而深证成指只含 500 只成分股。
3. **归因无据**：常写成"受消息刺激"，却说不出是哪条消息。
4. **合规返工**："有望""建议关注""后市可期"这类表述被退回，来回修改。
5. **质量参差**：不同投顾的覆盖面和口径不一致。

### 非目标
- 不预测涨跌，不给目标价、买卖或仓位建议，不承诺收益。
- 不直接面向散户输出，内容必须经持牌投顾修改、合规审核。
- 不替代合规审核；AI 复核只做提示，不作为放行依据。
- 不做按客户画像的个性化改写：只调整表达风格，事实不随受众改变。

### 成功标准
| 层级 | 指标 | 口径 | 目标（待验证的假设） |
|---|---|---|---|
| 北极星 | 单篇复盘从开始到合规通过的总时长 | 生成开始到 `approved_at` 的时间差 | 中位数比手工基线缩短 50% 以上 |
| 质量护栏 | 发布稿数字差错数 | 定稿中与接口原值不一致的数字个数 | 0（机制保证：数字只能由系统渲染） |
| 质量护栏 | 合规一次通过率 | 通过且从未被退回 ÷ 通过数 | ≥ 80% |
| 采纳 | AI 句子修改率 / 删除率 | 已提交稿件中被人修改 / 删除的 AI 句子占比 | 修改率 ≤ 40%，删除率 ≤ 20% |
| 系统 | 生成成功率、生成用时 | 产出草稿的次数 ÷ 发起次数；草稿就绪用时 | ≥ 95%；P50 ≤ 60 秒 |
| 风险 | 缺失数据被写成正常结论的次数 | 抽检存在 gaps 的稿件 | 0 |

除基线类指标外，以上指标在产品「价值指标」面板中都按同一口径实时计算。

## 2. 为什么需要 LLM / Agent

| 方案 | 能做到 | 做不到 |
|---|---|---|
| 规则模板（固定句式填数） | 数字准确、稳定 | 每天的主线不同，模板决定不了"今天该讲什么"，也无法把多源证据串成叙事。本产品保留它作为大模型故障时的**降级稿** |
| 搜索（新闻 / 问答搜索） | 找到大量资讯 | 不知道哪些和当天盘面相关，也不校验数字；结果混杂，实测 iFinD 检索也会返回百科页 |
| 传统数据产品（涨停复盘页、排行榜） | 表格齐全 | 停在"展示数据"这一步，判断主线、写成客户能读的话仍要靠人 |
| 人工 | 有判断力，是责任主体 | 慢、易抄错、质量参差 |
| **LLM + Agent + 确定性校验（本产品）** | 每天自主决定调查路径；把十几类结构化数据和文本证据组织成叙事；区分事实、推断与待确认；做语义层合规复核 | 数字不由它生成，由系统渲染；发布不由它决定，由人决定；数据缺失时不允许它"补全" |

**样例稿中 Agent 体现的增量**（2026-10-16 真实数据，见在线样例）：
- 把涨停原因里的「低空经济」（11 只）和「飞行汽车」（5 只）识别为同一主线。按标签计数的规则会把它们算成两个题材。随后它主动查询同花顺低空经济概念指数（上涨 2.02%）做印证。
- 发现出版方向个股连板，但出版行业指数只涨 0.10%，据此推断"更多是重组预期驱动的个股行情，而非板块整体"，并写成带"或"的推断句。规则做不出这种判断。
- 主动检索 iFinD 新闻，与同花顺异动解读交叉印证。发现新闻侧多为政策和科普类内容后，没有硬下归因结论，而是写成"当日催化尚待人工确认"的待确认句。
- 同一天的三次生成里，Agent 调用的工具和参数各不相同：会按当天盘面决定查哪些股票、哪些板块。

**多日评测**（最近 8 个交易日，每天真实生成一次，并与"大模型不可用"的模板稿对照，详见 [docs/EVAL.md](docs/EVAL.md)）：
- AI 稿每篇平均有 1.38 句带证据的归因（引用异动解读或新闻），模板稿为 0；关键事实覆盖率 AI 98%、模板 100%：AI 有一天漏写了当天出现次数最多的题材，产品里已为此加上"关键事实未覆盖"的提醒。
- 生成时校验器拦下 8 个阻断项（以搭配错误、张冠李戴、未溯源数字为主）。自修复处理 7 句，修好 6 句，最终剩 2 个阻断项交给人工；8 篇中有 7 篇修复后零阻断。
- 8/8 生成成功，平均 21.5 秒、27 次接口调用（Agent 自主 9.3 次）、约 3 万 token，接口零失败。样本只有 8 天，只说明护栏在不同行情日都在生效，不代表长期效果。

## 3. 产品闭环

| 环节 | 实现 |
|---|---|
| **数据** | 扶摇交易日历、指数日K（7 个指数）、涨停 / 跌停 / 炸板池、涨停统计、连板天梯、历史热股榜、日期范围异动解读、全 A 快照、同花顺行业 / 概念指数目录与日K、个股日K；iFinD MCP 新闻检索 |
| **工具** | Agent 通过 function calling 使用 5 个工具：异动原因、题材成员、板块指数涨跌、个股累计涨幅、iFinD 新闻。最多 3 轮，每轮最多 4 个调用；每次调用记录参数、耗时、重试次数、request_id、数据时间 |
| **状态** | 每次生成存为一条记录，包含事实底稿、证据、缺失项、核验提示、调用日志、Agent 过程和草稿；状态机：草稿 → 待合规审核 → 已通过 / 已退回 → 修改后再提交 |
| **反馈** | 逐句 👍/👎（附原因）；修改、删除、新增句子都留痕；「价值指标」面板统计修改率、删除率、一次通过率、生成时拦截分布、👎 原因分布。**反馈不止于统计**：合规在「规则库」里把退回原因沉淀为禁用表述，投顾把反复修改的写法沉淀为写作偏好；它们立即作用于所有草稿的校验，并写进之后每次生成的撰写提示词 |
| **人机协作** | AI 起草并标出不确定性；投顾编辑（保存即重新校验；点击事实编号可插入引用），逐条确认待确认项；合规审核通过或退回（退回必须填写意见）；通过后才生成定稿 |
| **风险控制** | 数字占位符渲染、实体一致性与搭配校验、合规词表加 AI 语义复核、校验器在环的自修复、发布门禁、缺失不补齐、单 IP 限流（默认每小时 8 次，线上 30 次）、全局并发上限（默认 3） |

### AI、系统、人的分工
| 谁 | 负责 | 不负责 |
|---|---|---|
| 大模型（Agent） | 判断主线、决定补查哪些证据、合并同义题材；把结论写成"判断 + 支持 + 反证 + 待补" | 生成或修改任何数字；给出没有证据的结论（会被降为"存疑"） |
| 大模型（自修复） | 按校验器给出的错误原因重写 AI 写的问题句 | 改动人写的句子；绕过校验（修订稿必须重新通过校验才会被采用） |
| 大模型（撰写） | 组织叙事，标注句子类型和依据编号 | 自行引入证据之外的新闻、政策、资金结论 |
| 大模型（复核） | 找出隐含预测、变相建议等语义问题，给出改写建议 | 放行或驳回 |
| 确定性系统 | 取数、算派生值（涨跌幅、两市成交额、涨跌家数）、渲染数字、交叉核验、规则拦截、门禁 | 判断主线 |
| 投资顾问 | 修改、确认待确认项、提交 | — |
| 合规 | 最终放行或退回 | — |

## 4. 数据来源与口径

| 数据 | 接口 | 口径要点 |
|---|---|---|
| 交易日 | `/api/a-share/calendar/trading-days` | 非交易日、未来日期、未收盘日期直接拒绝，并给出最近可用交易日 |
| 指数收盘与涨跌幅 | `/api/a-share-index/prices/historical` | 按所选日期取日K收盘价；涨跌幅 = 当日收盘 ÷ 前一交易日收盘 − 1。**不用快照**：快照的 timestamp 是查询时刻 |
| 两市成交额 | 同上（000001.SH + 399106.SZ） | 上证综指成交额 + 深证综指成交额。不能用深证成指，它只含 500 只成分股 |
| 涨停 / 炸板 / 封板率 / 连板 | `/api/a-share/special-data/limit-up-statistics` | 校验 `trade_date` 与所选日一致，不一致整块弃用；封板率与家数做自洽校验 |
| 涨停池、跌停池、炸板池 | `limit-up-pool` / `limit-down-pool` / `limit-break-pool` | 与统计接口交叉核验（2026-10-16：涨停池 59 = 统计涨停 59，炸板池 49 = 统计炸板 49） |
| 题材 | 涨停池 `limit_up_reason` | 按"+"拆分计数，同一股票可属于多个题材；同义合并交给 Agent |
| 连板天梯 | `limit-up-ladder` | 近 30 个交易日，用于交叉核验最高板 |
| 热度 | `hot-stock-list-history` | 按自然日取的历史榜单 |
| 异动原因 | `/api/news/anomaly/analysis` | 同花顺 AI 汇总的公开信息，以公告为准；按 `link_url` 中的 `thsHqCode` 匹配个股 |
| 涨跌家数 | `/api/a-share/prices/snapshot`（全 A 分页） | **只有当快照等于所选日收盘口径时才出具**（所选日是最近收盘日，且当前不在下一交易日盘中）；否则标为缺失 |
| 板块指数 | `ths-index-list` + 指数日K | Agent 按关键词匹配后计算当日涨跌幅 |
| 新闻 | iFinD MCP `hexin-ifind-ds-news-mcp / search_news` | 时间窗为所选日前 3 天至当日，晚于所选日的结果丢弃；百科类来源标注"慎用" |

每个数字在右侧「事实底稿」都能看到字段路径、时点、口径、端点、调用编号和 request_id。

## 5. 风险控制与合规边界

1. **数字溯源**：写作提示要求正文不出现任何阿拉伯数字，数字一律写成 `{{F编号}}`，由系统按原值渲染。校验器去掉占位符和白名单实体名（如"沪深300"）后，剩下的数字一律判为**阻断项**。
2. **张冠李戴拦截**：带个股属性的事实，所在分句必须出现该股票名，否则判为阻断。这条规则来自开发中真实发生的错误：模型把新华传媒的近 5 日涨幅写到了阳光乳业名下。
3. **合规三层**：关键词规则（预测、荐股、收益承诺为阻断，夸张措辞为提醒）→ AI 语义复核（隐含预测、变相建议，只做提示）→ 合规人工审核（放行权）。
4. **事实、推断、待确认三分**：推断必须给出依据编号，并带"或""可能"等不确定措辞；事实句夹带判断时提醒拆分。
5. **缺失不补齐**：接口失败、日期不符、数据过期、样本不全时，对应数据块写入「数据缺失」，正文只能写成待确认句。待确认句必须由投顾逐条确认，否则无法提交。交易日历失败时整次生成中止，不产出任何结论。
6. **降级**：大模型失败或超时时，改出模板数据底稿，只复述事实、不含推断，并显式标注"需人工补写"。
6b. **自修复（校验器在环）**：AI 写的句子没有通过校验时，带着校验器的错误原因交还模型重写一轮；修订稿必须重新通过同一套校验才替换原句，否则保留原句与问题标记交给人工。人写的句子从不被自动改动。
6c. **团队规则**：合规在「规则库」里新增的禁用表述会立即参与所有草稿的校验（打开草稿时按最新规则重算），并写进撰写提示词，从源头减少同类问题。
7. **发布门禁与审计**：阻断项为 0 且待确认全部处理后才能提交；只有合规通过才生成定稿，定稿自动附上数据来源与风险提示。生成、修改、确认、反馈、提交、审核全程写入审计日志。
8. **隐私与密钥**：产品不需要任何客户画像或持仓数据，演示中也不含用户数据；所有 Key 只通过环境变量注入，仓库中没有密钥。
9. **模型选择**：选用境内模型服务（DeepSeek）。真实上线前需按机构流程评估生成式 AI 服务的合规要求；本产品定位为机构内部的生产工具。

## 6. 失败条件

**产品层面（出现以下情况说明方向不成立，需要调整）**
- 投顾对 AI 句子的修改率长期超过 50%，或删除率很高：草稿没有省时间，应退化为"数据底稿 + 证据面板"形态，不再出成稿。
- 合规不接受任何 AI 推断句（即使有依据）：价值降为取数工具，应改成只出事实句和证据清单。
- 盘后数据就绪太晚：例如收盘后很久统计接口的 `trade_date` 仍是前一日，产品就无法"收盘后 10 分钟出稿"，需要加入等待和重试机制。
- 推断质量不稳定：👎 原因中"归因牵强"占比居高不下。

**系统层面（会失败的地方，以及失败时用户看到什么）**
| 情况 | 表现 |
|---|---|
| 扶摇某个接口失败或超时（429 / 5xxx 会自动重试 2 次） | 对应数据块标为缺失，章节出现待确认句，必须确认后才能提交 |
| 交易日历失败 | 生成中止，提示原因，不产出任何结论 |
| 大模型失败、超时或输出非法 JSON（会先重试 1 次） | 降级为模板底稿，页面顶部标注"已降级" |
| 模型编造数字或张冠李戴 | 校验器判为阻断，无法提交 |
| 隐含预测绕过词表 | 由 AI 复核层提示，最终靠合规人工把关（残余风险） |
| iFinD 不可用 | Agent 收到"工具失败、证据缺失"，继续用扶摇数据，不据此下结论 |
| Render 免费实例 | 闲置休眠，冷启动约 30–60 秒；重启后运行记录清空（仓库内样例保留） |

## 8. 快速开始

```bash
git clone https://github.com/Yuyang16Z/recap-desk.git
cd recap-desk
npm install
cp .env.example .env.local   # 填写 FUYAO_API_KEY、DEEPSEEK_API_KEY（IFIND_MCP_TOKEN 可选）
npm start                    # http://localhost:3000
```

```bash
npm test                                                     # 单元测试（离线，不调用真实接口）
node scripts/eval.mjs --days=8                               # 多日评测：真实接口逐日生成并与模板稿对照，输出 docs/EVAL.md
node scripts/smoke.mjs --date=2026-10-16 --audience=steady   # 用真实接口跑一次完整生成并打印草稿
node scripts/smoke.mjs --simulate=llm_down,inject_violation  # 故障演练示例
```

| 环境变量 | 必填 | 说明 |
|---|---|---|
| `FUYAO_API_KEY` | 是 | 扶摇 API Key（https://fuyao.aicubes.cn/admin 签发） |
| `DEEPSEEK_API_KEY` | 是（不填则降级为模板底稿） | DeepSeek Key |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-chat`；`AGENT_MODEL` / `WRITER_MODEL` 可分别覆盖 |
| `DEEPSEEK_BASE_URL` | 否 | 默认 `https://api.deepseek.com`，可换成其他 OpenAI 兼容服务 |
| `IFIND_MCP_TOKEN` / `IFIND_MCP_BASE` | 否 | iFinD MCP 新闻检索 |
| `RUNS_PER_IP_PER_HOUR` | 否 | 单 IP 每小时生成上限，默认 8（线上设为 30，便于同一办公网络的多位评审试用） |
| `MAX_ACTIVE_RUNS` | 否 | 同时进行的生成任务上限，默认 3 |
| `PORT` | 否 | 默认 3000 |

部署：Render Web Service（Node 22，`npm install` / `node server.js`，健康检查 `/api/health`，新加坡区）。环境变量在 Render 控制台注入。

## 10. 已知边界与未做事项

- **涨跌家数**只支持最近收盘日（快照接口只提供最新行情），历史日期标为缺失；全市场历史日K需要下载 Parquet 导出文件，本次未做。
- **全行业板块排名**没做（需要 300 多次指数调用），改由 Agent 按需查询相关板块。
- **资金流向**（主力资金）没接入：扶摇的该接口仅在同花顺 AI 客户端内提供。iFinD 的宏观（EDB）和公告检索也未接入，目前只接了新闻检索。
- **规则库权限**：按页面上选择的角色区分（只有「合规审核」能增删禁用表述），没有真正的身份认证。
- **账号与权限**：右上角的角色切换只用于演示。真实部署需要 SSO、角色权限，以及"投顾不能审核自己的稿件"这类约束。
- **存储**：本地 JSON 文件，Render 免费实例重启后清空（样例除外）；生产环境需要数据库。
- **AI 合规复核**只做提示，不作为放行依据。
- **来源措辞**：模型偶尔会把 iFinD 新闻说成"异动解读"。依据编号指向的真实来源可以在右侧面板核对，但正文措辞仍需人工复核。
- **评测规模**：多日评测只覆盖 8 个交易日、一种受众、每天一次运行，不能代表长期稳定性；文字质量的主观好坏，仍需要第 7 节的真人对照实验来验证。
- 未对接企业微信或 APP 推送等发布渠道。
